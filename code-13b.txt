# 13(b) Terraform AWS Infrastructure

## Aim

To use Terraform to provision an **EC2 t2.micro instance**, an **S3 bucket for ML models**, a **security group allowing only ports 22 and 8000**, and an **S3 backend with DynamoDB state locking**, followed by `init → plan → apply` and output verification.

Terraform uses `aws_instance` for EC2 and the AWS provider for managing AWS resources. ([Terraform Registry][1])

> **Note:** This creates real AWS resources. Use a lab/free-tier account and destroy them afterward if you don't need them.

---

## Step 1: Prerequisites

Make sure these work:

```powershell
terraform --version
aws --version
aws configure
```

`aws configure` will ask for your AWS access key, secret key, region, etc. Terraform can use the same AWS credential configuration as the AWS CLI. ([Sentinel | HashiCorp Developer][2])

---

## Step 2: Create project

Create:

```text
terraform-ml
```

Inside it create:

```text
main.tf
variables.tf
outputs.tf
```

---

## Step 3: `variables.tf`

```hcl
variable "region" {
  default = "us-east-1"
}

variable "state_bucket" {
  default = "student-ml-terraform-state-12345"
}

variable "model_bucket" {
  default = "student-ml-models-12345"
}
```

**Important:** Change `12345` to some unique number/name because S3 bucket names must be unique.

---

## Step 4: `main.tf`

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = var.region
}

# -------------------------
# EC2 Security Group
# -------------------------

resource "aws_security_group" "ml_sg" {
  name = "ml-security-group"

  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    from_port   = 8000
    to_port     = 8000
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# -------------------------
# Ubuntu AMI
# -------------------------

data "aws_ami" "ubuntu" {
  most_recent = true

  owners = ["099720109477"]

  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd-gp3/ubuntu-noble-24.04-amd64-server-*"]
  }

  filter {
    name   = "virtualization-type"
    values = ["hvm"]
  }
}

# -------------------------
# EC2 Instance
# -------------------------

resource "aws_instance" "ml_server" {
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t2.micro"

  security_groups = [aws_security_group.ml_sg.name]

  tags = {
    Name = "Student-ML-Server"
  }
}

# -------------------------
# S3 Model Bucket
# -------------------------

resource "aws_s3_bucket" "model_bucket" {
  bucket = var.model_bucket
}

# -------------------------
# Terraform State Bucket
# -------------------------

resource "aws_s3_bucket" "state_bucket" {
  bucket = var.state_bucket
}

# -------------------------
# DynamoDB Lock Table
# -------------------------

resource "aws_dynamodb_table" "terraform_lock" {
  name         = "terraform-state-lock"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "LockID"

  attribute {
    name = "LockID"
    type = "S"
  }
}
```

The AWS provider supports resources such as EC2, S3 and DynamoDB, and Terraform's `resource` blocks are used to define infrastructure. ([Terraform Registry][3])

---

## Step 5: `outputs.tf`

```hcl
output "ec2_public_ip" {
  value = aws_instance.ml_server.public_ip
}

output "model_bucket" {
  value = aws_s3_bucket.model_bucket.bucket
}

output "state_bucket" {
  value = aws_s3_bucket.state_bucket.bucket
}

output "security_group" {
  value = aws_security_group.ml_sg.id
}
```

# Step 6: Initialize Terraform

Inside the folder:

```powershell
terraform init
```

---

# Step 7: Validate

```powershell
terraform validate
```

Expected:

```text
Success! The configuration is valid.
```

# Step 8: Plan

```powershell
terraform plan
```

You should see resources that will be created:

```text
aws_security_group
aws_instance
aws_s3_bucket
aws_s3_bucket

```

# Step 9: Apply

```powershell
terraform apply
```

When asked:

```text
Enter a value:
```

```text
yes
```

# Step 10: Check Outputs

```powershell

```

You should get something similar to:

```text

```

# Step 11: Configure S3 Backend + DynamoDB Locking

After the resources have been created successfully, add this inside the `terraform` block in `main.tf`:

```hcl
backend "s3" {
  bucket         = "student-ml-terraform-state-12345"
  key            = "terraform.tfstate"
  region         = "us-east-1"
  dynamodb_table = "terraform-state-lock"
}
```

**Change the bucket name to exactly the same value you used in `state_bucket`.**

Then run:

```powershell
terraform init -migrate-state
```

When Terraform asks whether to copy the existing local state to the new S3 backend, enter:

```text
yes
```

Now the Terraform state is stored in S3 and DynamoDB provides the state locking mechanism.
